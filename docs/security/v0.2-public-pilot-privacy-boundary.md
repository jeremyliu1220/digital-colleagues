# v0.2 Public Pilot Privacy Boundary

Status: P9 planning contract. No v0.2 connector, credential store, external-source
processing, or live acceptance is implemented by P9.

## Public/private boundary

The public tree must never contain a real account, tenant, App/provider identifier,
endpoint, email/chat/task/document identifier or body, provider receipt, live acceptance,
personal data, credential, database, backup, log, cache, diagnostic, or local absolute
path. No one is asked to paste a credential into conversation or source control.

Public P9-P14 evidence may be `static`, `synthetic_offline`, or explicitly `loopback`.
`live_private` and `human_evaluation` belong to private stores outside the public tree.
Mock, stub, or loopback results cannot be relabeled as live or named-provider compatibility.

## Secrets

- Mac live mode checks FileVault before receiving credentials.
- The secrets directory is mode `0700`; each credential file is mode `0600`.
- A credential is mounted read-only only into the service that needs it.
- Keys and tokens are forbidden from environment variables, SQLite, audit, backups,
  diagnostics, logs, errors, command arguments, public evidence, UI state, and package
  content.
- Always-on Linux uses an operator-provided encrypted volume. If storage encryption cannot
  be proven, live readiness remains `not_evaluated` or live mode is blocked.
- Revocation invalidates the ExternalConnection, dependent ConnectorGrants, and pending
  effects. Refresh and revoke failures are finite safe states.

The OpenAI key, Microsoft delegated tokens, Entra App configuration, account identity, and
all live receipts remain operator-private. The distinction between a project-operated
multi-tenant public client and BYO single-tenant public client is recorded without putting
real IDs into public material.

## External source processing lifecycle

The default durable representation is a SourceReference, SourceCursor, etag/version,
content digest, bounded safe projection, and causal record. Full Outlook messages, Teams
messages, and SharePoint document bodies are not persisted. Planner stores only fields
required by exact governed work/effect semantics, subject to the same minimization.

The future connector processing contract is:

1. authenticate an exact current ExternalConnection;
2. revalidate its exact ConnectorGrant, namespace, resource, action, and budget;
3. fetch at most the configured byte/item/time window;
4. keep raw bytes in process memory or an OS-private bounded temporary file only when
   streaming requires it;
5. normalize and redact to the minimum model/source context;
6. compute SourceReference, cursor, etag/version, digest, and safe projection;
7. submit only bounded required context to the server-controlled decision path;
8. discard full content immediately after the decision attempt, whether success, refusal,
   timeout, incomplete response, schema error, or cancellation;
9. on process restart, remove connector-owned temporary files before resuming cursors; and
10. never reconstruct missing source text from logs, audit, diagnostics, or public evidence.

Temporary source maximums, MIME/type allowlist, download redirect policy, redaction rules,
discard deadline, crash directory, and cleanup counter must be fixed and mechanically
tested by P13 before use. Unknown type/size, unbound resource, stale cursor/etag, partial
cleanup, or ambiguous ownership fails closed.

## Provider minimization

P12 sends OpenAI only the bounded prompt layers and source/work projection needed for one
semantic decision, explicitly sets `store:false`, exposes no tools or credentials, and
records only safe model provenance, usage, status, and schema result. Provider output is
untrusted and cannot carry authoritative namespace, role, connection, grant, approval, or
effect bindings.

P13 uses delegated Microsoft 365 access for one dedicated work/school account per Agent.
Outlook cursors are per folder; Teams polling is restricted to Admin-allowlisted chats and
a bounded date window; Planner uses current ETag; SharePoint reads selected sites/folders
only. Cross-Agent and cross-tenant content access is denied by default.

## Retention, deletion, and diagnostics

SourceReferences/Cursors and safe causal records follow a future explicit retention and
deletion policy. They do not form Semantic Memory, embeddings, a synthesized-fact store,
or learning loop. S1 remains independently gated. Package prompts and localization do not
grant permission to retain more data.

Public diagnostics remain allowlisted and content-free. Private operational diagnostics
must still exclude credentials, source bodies, response bodies, URLs/endpoints, local
paths, environment values, and unbounded errors. Backup remains operator-private and is
not a permitted credential store.

## i18n privacy invariant

`zh-TW` and `en-US` display text may explain the same data handling differently, but
consent, retention, selected-resource, redaction, and permission semantics are identical.
A missing translation cannot enable collection, retention, disclosure, or execution.

## P15 private live boundary

Live acceptance needs two Microsoft 365 test tenants, ten dedicated Agent test accounts,
one usable OpenAI test project, a verified project multi-tenant Entra public-client App, a
BYO single-tenant App, delegated user- and Admin-consent testing, real test data across
Outlook/Teams/Planner/SharePoint, and private acceptance storage outside the public tree.
Public artifacts may contain only sanitized aggregate classifications and cannot include a
live receipt or personal evaluation.

## Claim boundary

A clean P9 privacy gate proves only that static public files and synthetic fixtures matched
this contract. It proves no live provider privacy, retention behavior, encrypted storage,
regulatory compliance, production tenancy, production security, or production readiness.
