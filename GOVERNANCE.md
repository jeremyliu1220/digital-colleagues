# Governance

Digital Colleagues uses maintainer review during its pre-release milestones.

- Maintainers merge changes, enforce milestone scope, and keep acceptance evidence honest.
- Project-owner approval is required for licensing direction, public release, and changes
  that expand the project's authority or claim boundary.
- A privacy or security reviewer must approve any exact scanner exception in the role
  permitted by the exception ledger.
- Rights uncertainty blocks the affected file until documented review resolves it.
- Architecture changes that alter stable boundaries require an ADR.

Technical decisions prefer reproducible evidence and documented tradeoffs. Maintainers may
not use governance roles to bypass the public-boundary, source-rights, principal-kind, or
human-approval rules. The project will document a broader maintainer nomination and appeal
process before its first supported release.
